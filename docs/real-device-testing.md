# 真机验证指南

电脑上的自动化浏览器没有真实摄像头、触摸屏、GPS，也没有 iOS Safari，下面这些**只能人手在真机上走一遍**。本文给出怎么让手机连上本机的开发环境，以及逐条清单。清单里每条都写了「预期」，不符就记下机型、系统版本、浏览器版本和现象。

> 状态：这份指南是照代码和浏览器行为写的，**还没有人真的照着在手机上走过**。第一次走时发现步骤不对，直接改这个文件。

## 一、Android（Chrome）：USB 端口转发，不需要 HTTPS

手机把 `localhost` 当安全来源，所以相机（`getUserMedia`）和定位都能用，不用装证书、不用隧道。

1. 手机：设置 → 关于手机 → 连点「版本号」开启开发者选项 → 打开「USB 调试」。用数据线接电脑，手机弹窗里点「允许」。
2. 电脑起好环境（见 `web/README.md`「从零到…」）：模拟器已启动并灌好数据，`cd web && npm start` 在跑。
3. 电脑 Chrome 打开 `chrome://inspect/#devices`，勾选「Discover USB devices」，点「Port forwarding…」，加三条（右边都写 `localhost:` 加同一个端口）：

   | 手机端口 | 电脑 |
   | --- | --- |
   | 4200 | localhost:4200 |
   | 9099 | localhost:9099 |
   | 8080 | localhost:8080 |

   勾上「Enable port forwarding」保存。**三条都要**：开发配置里 Auth 连 `127.0.0.1:9099`、Firestore 连 `127.0.0.1:8080`（`web/src/environments/environment.development.ts`），手机上的 `127.0.0.1` 要靠转发才到电脑。
4. 手机 Chrome 打开 `http://localhost:4200`。登录用模拟器测试号（`web/README.md` 有清单；验证码从模拟器 REST 取）。
5. 想看手机页面的控制台：回到 `chrome://inspect/#devices`，那台设备下面点「inspect」。

连不上时先查：数据线是否只充电、`chrome://inspect` 里设备是否显示、转发是否三条都在、电脑上 `4200`／`9099`／`8080` 是否真在监听。

## 二、iOS（Safari）：需要 HTTPS

iOS Safari 只在 HTTPS（或 `localhost`）下开放相机，而 iPhone 没法像 Android 那样做端口转发，所以要有一个**公网 HTTPS 地址**。两条路：

- **部署出去再测（推荐）**：等后端同学把 Firebase 项目和 Hosting 定下来（见根 README「队友处理须知」），部署后直接用线上地址测。这条路最接近评委看到的样子。
- **临时隧道**：用 Cloudflare Tunnel、ngrok 一类工具给 `localhost:4200` 一个 HTTPS 地址。注意两个坑：① 开发服务器默认只认自己的主机名，隧道域名要加进允许列表（`ng serve --allowed-hosts <域名>`），否则页面打不开；② 开发配置里 Auth／Firestore 指向 `127.0.0.1`，手机上的 `127.0.0.1` 是手机自己，登录和读数据都会失败——要么把 9099、8080 也各开一条隧道并临时改环境文件（**别提交这个改动**），要么直接测部署版。

只想先验证相机／取景流程时，可以用相册入口代替，但这就测不到相机本身，不算过。
